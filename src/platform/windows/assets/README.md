# clipss2 application icon

The SVG is the editable master. The ICO is the adopted Windows resource, with
16, 24, 32, 48, 64, 128 and 256 pixel RGBA PNG frames. Intermediate PNG files and
review previews are generated under `build/` and are not source assets.

| Canvas | 256 × 256, front-facing, no perspective or text |
| Plate | x/y 16, width/height 224, corner radius 48 |
| Background gradient | `#164D83` to `#123761` |
| Top left / bottom right | `#F4F8FC` |
| Top right / bottom left | `#54D6EC` |
| L frames | stroke 24, arms 48, butt caps, round joins |
| Frame centerlines | 64 and 192, arm endpoints 112 and 144 |
| Transparency | Outside the plate; the center remains opaque blue |

At 16 px the plate is 14 px wide, the outer inset is 1 px, the stroke is 1.5 px
and the gaps are 2 px. All sizes use the same geometry; no small-size variants.

## Regeneration

Use Node.js 24 or newer and an already installed Chromium-based browser. The
validated versions were Node.js 24.22.1 and Microsoft Edge 156.0.4314.50 / 156.0.4314.58 on Windows.
No npm packages, external artwork or network download are required. Edge is found
under the Windows Program Files environment variable; set `ICON_BROWSER` to use
another browser executable.

From the repository root, choose an output directory that does not exist:

```powershell
node src/platform/windows/assets/generate.mjs --output build/icon-regenerated-01
pwsh -NoProfile -File src/platform/windows/assets/validate.ps1 -AssetRoot build/icon-regenerated-01
```

The generator reads this SVG, renders each PNG directly, packs those PNG bytes
into the ICO, creates light/dark review previews and writes validation/hash files.
It uses a private temporary browser profile and a loopback DevTools connection.
Only its newly created profile is removed at exit. Existing output directories
are refused. The adopted source SVG/ICO are never overwritten by this command.
The independent validator uses Windows WPF through PowerShell 7.2 or newer.
Browser/OS versions can affect rasterization and compression, so compare pixels
and review the images before adopting regenerated bytes.

Node.js is separately licensed under MIT with its own
[third-party notices](https://github.com/nodejs/node/blob/v24.x/LICENSE);
Microsoft Edge is a separately licensed Microsoft product. Windows WPF/.NET is
provided by the installed Windows/.NET environment. These are local execution

bundled with the icon assets or newly added to the application's dependencies.

## Windows integration

`../app_icon.rc.in` embeds `clipss2.ico` as `IDI_CLIPSS2_APP` (101), defined in
`../app_resources.h`. It is separate from the unchanged VERSIONINFO template and
the existing application manifest. CMake explicitly tracks ICO/header changes as
resource compilation dependencies.

Settings applies per-window small/large icons with `WM_SETICON` and reloads them
when DPI changes. It requests `WS_EX_APPWINDOW` so a Settings window owned by the
hidden resident can appear on the taskbar. Internal control/capture windows are
unchanged. See the [Win32 extended styles reference](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles).

`../app_icon.h` uses owned `LoadImageW` icons instead of `LR_SHARED` size caching.
The previous window icon is released after its replacement is installed. Missing
resources fall back to an owned copy of the stock icon; failure of both loads
does not throw. Shared stock handles are never destroyed. See the
[Win32 icon ownership rules](https://learn.microsoft.com/en-us/windows/win32/menurc/using-icons).

The tray uses system-DPI small-icon metrics, refreshes for settings/display/DPI
notifications and reloads on `TaskbarCreated` recovery. `Shell_NotifyIconW` is
updated before the previous owned handle is released. Mixed-monitor/taskbar DPI
behavior still requires actual desktop acceptance.

See [ICON-2 local validation](../../../../docs/ICON-2-VALIDATION.md) for the isolated
build path, PE inspection and manual acceptance checklist.
